# Публичный сайт Полки

Hugo + [Hugo Book](https://github.com/alex-shpak/hugo-book). Исходники сайта находятся только в `polka-docs`; соседний репозиторий продукта не используется. Никаких Node.js, npm или базы данных не требуется.

## Требования

- Git.
- Hugo **extended**, версия 0.158.0 или новее. Проверено на 0.167.0.

На macOS: `brew install hugo`.

## Первый запуск

Из каталога `polka-docs`:

```sh
git submodule update --init --recursive
hugo server --bind 127.0.0.1 --port 1314 --renderToMemory --buildDrafts
```

Открыть <http://localhost:1314/>. Hugo автоматически обновляет страницы при редактировании файлов. В VS Code можно запустить задачу **Hugo: Serve Polka Docs**.

Локальный сервер включает черновики, чтобы были видны незавершённые документы и примеры. Чтобы открыть только опубликованный контент, запустите `hugo server --bind 127.0.0.1 --port 1314 --renderToMemory` без флага `--buildDrafts`. Остановить сервер: `Ctrl+C`. Обычная сборка также не включает черновики.

## Структура

```text
content/
  _index.md           Главная
  about/              О Полке, вопросы и ответы
  documents/          Оферта, конфиденциальность, соглашение
  releases/           Публичные заметки об обновлениях
archetypes/           Шаблоны новых страниц
layouts/             Списки документов и релизов, логотип
assets/styles/       Небольшие дополнения к стилям темы
themes/hugo-book/    Тема как Git submodule
hugo.toml            Конфигурация
```

Юридические страницы и релиз 1.2 — **черновики-заготовки**, а не действующие документы или реальные объявления. В публичной сборке разделы показывают сообщение, что публикаций пока нет. Описание продукта также нужно дополнить реальными сведениями.

## Добавление документов

```sh
hugo new content documents/new-document.md
```

Заполните заголовок, согласованный текст и `effectiveDate` (дата вступления в силу, `YYYY-MM-DD`). Для публикации замените `draft: true` на `draft: false`. Поле `weight` управляет порядком в списке и меню. URL задаётся именем файла; сохраняйте его при обновлении документа, чтобы не ломать ссылки.

## Публичные релизы

```sh
hugo new content releases/1.3.md
```

Для публичных заметок планируются версии уровня **X.Y**: 1.1, 1.2, 2.0. Выбор версий будет определяться редакционным процессом через skill. Hugo не проверяет и не ограничивает формат версий; поле `version` в шаблоне служит для хранения номера версии.

Заполните `description`, дату `date` с часовым поясом и текст; установите `draft: false`. Список релизов автоматически сортируется по дате от новых к старым. `bookHidden: true` убирает отдельные релизы из бокового меню; они остаются в списке раздела, поиске и RSS `/releases/index.xml`. Сайт не получает версии из репозитория продукта автоматически — редактор публикует заметки вручную.

## Сборка и будущий поддомен docs

```sh
hugo --gc --minify --cleanDestinationDir
```

Готовый статический сайт — в `public/` (исключён из Git). `--cleanDestinationDir` удаляет устаревшие файлы сборки, в том числе страницы, которые снова перевели в черновики. Для публикации нужно будет заменить локальный `baseURL` в `hugo.toml` на полный адрес `https://docs.ВАШ-ДОМЕН/` или передать его при сборке:

```sh
hugo --gc --minify --cleanDestinationDir --baseURL https://docs.example.com/
```

В production не используйте `--buildDrafts`. Каталог `public/` можно разместить на любом статическом хостинге. DNS, хостинг и публикация пока не настроены.

## Тема и обновления

Тема подключена стандартным Git submodule: родительский репозиторий фиксирует конкретный коммит, поэтому клонирование воспроизводит ту же версию.

Клонировать будущий репозиторий сайта нужно с `git clone --recurse-submodules …`, либо затем выполнить `git submodule update --init --recursive`.

Обновить тему до актуального `main`:

```sh
git submodule update --remote themes/hugo-book
hugo --gc --minify
git add themes/hugo-book
git commit -m "Update Hugo Book theme"
```

Перед коммитом проверьте страницы локально: обновления темы могут менять совместимость и минимальную версию Hugo. Собственные шаблоны и стили лежат вне темы — файлы в `themes/hugo-book` не редактируем.

Русский язык, поиск, светлая тема и мобильная навигация настроены средствами Hugo Book. Комментарии, внешняя аналитика и offline-кэширование не включены.

Шрифт Onest хранится локально в `static/fonts/Onest.ttf` (копия из продукта). Подключение шрифта и начертание логотипа настроены в `assets/styles/custom.css`; текст логотипа — параметром `BookBrand` в `hugo.toml`. Расположение логотипа на широком и мобильном экране задаёт тема.
